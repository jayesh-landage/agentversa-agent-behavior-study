# Ethics and Limitations

## 1. Educational Simulation

This project examines fictional agent behavior in the AgentVersa/JusticeNet/LegalVerse simulation. It is not real legal work, legal advice, a binding determination, or a finding about any real person.

## 2. Authority Boundaries

The shared simulation rules state that agents advise but cannot issue binding rulings, file actual charges, punish anyone, contact a person, access a system, or publish information outside the simulation.

The fictional panel charter assigns binding orders and referrals to a human panel.

## 3. Evidence and Uncertainty

Records may contain unverified statements or disputed interpretations. A report that someone made a statement does not prove the underlying allegation.

Account use does not by itself identify a person or prove misconduct. An undocumented access interval does not automatically establish that a file was altered. A timestamp must be interpreted according to the clock and provenance limitations supplied in the packet.

## 4. Traceability

Claims about NyayaSetu's individual behavior should be supported by identifiable episode records.

Collective simulation reports should be described as collective reports, not substituted for individual agent responses.

If an individual record is unavailable, that limitation should be disclosed rather than filled with an invented response.

## 5. Model and Simulation Limitations

Observed behavior may be affected by:
- Scenario design and wording.
- Prompts and agent configuration.
- Model variability.
- Information supplied or withheld.
- Memory and previous agent statements.
- Interactions and relationships between agents.
- Platform constraints.
- The limited number of episodes reviewed.

A small number of simulated episodes cannot establish stable reliability, fairness, safety, or professional competence.

## 6. Researcher Limitations

The researcher interprets the available records. Observations must be distinguished from interpretations, and alternative explanations should be considered.

Predictions should not be rewritten after viewing results. Proposed design changes should not be described as improvements unless tested.

## 7. Privacy

The project should use only fictional scenario material and information necessary for the educational research. Unnecessary confidential or personally identifiable information should not be included.

## 8. Appropriate Use

This repository is a research and learning portfolio. Its contents should not be used as evidence of real-world guilt, legal responsibility, or production suitability.
